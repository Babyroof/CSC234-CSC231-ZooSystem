# CLAUDE.md — Zoopernova Zoo System

## Project Overview

Flutter + Firebase mobile application for zoo visitors. Users can browse animal and event information, book tickets with add-ons, navigate the zoo using an interactive map, and manage their profile and booking history. Includes an admin web dashboard for content management.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Mobile | Flutter (Dart) — Android + Web |
| Admin Dashboard | Flutter Web |
| Database | Firebase Firestore |
| Auth | Firebase Auth (Email/Password + Anonymous/Guest) |
| Storage | Firebase Storage (map image, animal/event photos) |
| Payment | Omise Payment Gateway |
| State | Riverpod 2.x (with code generation) |
| Routing | GoRouter (`lib/core/routes/`) |
| CI/CD | GitHub Actions (`.github/workflows/ci.yml`) |
| Dev Tools | Claude AI (AI assistance), VS Code (local dev) |

## Firestore Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isLoggedIn() {
      return request.auth != null;
    }
    function isAdmin() {
      return isLoggedIn() &&
        exists(/databases/$(database)/documents/admin/$(request.auth.uid));
    }
    function isOwner(uid) {
      return isLoggedIn() && request.auth.uid == uid;
    }

    match /settings/{docId} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /animal/{id} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /zone/{id} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /event/{id} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /map/{id} {
      allow read: if true;
      allow write: if isAdmin();
    }
    match /addOns/{id} {
      allow read: if isLoggedIn();
      allow create, update, delete: if isAdmin();
    }
    match /config/{id} {
      allow read: if isLoggedIn();
      allow create, update, delete: if isAdmin();
    }
    match /booking/{id} {
      allow create: if isLoggedIn()
        && request.resource.data.date is timestamp
        && request.resource.data.date > request.time;
      allow read: if isAdmin() ||
        (isLoggedIn() && resource.data.userId == request.auth.uid);
      allow update: if isAdmin() ||
        (isLoggedIn() && resource.data.userId == request.auth.uid);
      allow delete: if isAdmin() ||
        (isLoggedIn() && resource.data.userId == request.auth.uid);
    }
    match /user/{uid} {
      allow read: if isAdmin() || isOwner(uid);
      allow create: if isOwner(uid);
      allow update: if isOwner(uid)
        && request.resource.data.diff(resource.data).affectedKeys()
            .hasOnly(['username', 'firstname', 'lastname', 'phoneNumber']);
      allow delete: if isOwner(uid);
    }
    match /admin/{uid} {
      allow read: if isOwner(uid);
      allow create: if isOwner(uid);
      allow update, delete: if false;
    }
  }
}
```

## Coding Rules (All Agents Must Follow)

- ❌ Never use `setState` — use Riverpod controllers only
- ❌ Never call Firestore directly from a screen or widget — always go through `services/`
- ❌ Never hardcode colors — use `core/themes/` tokens
- ❌ Never hardcode credentials or API keys in `.dart` files
- ❌ Never commit `firebase_options.dart`, `google-services.json`, or `GoogleService-Info.plist`
- ❌ Never use Auto-ID for `user` documents — Document ID must equal Firebase Auth UID
- ❌ Never store `userId` as a Firestore Reference in `booking` — store as plain Auth UID string
- ✅ Each feature is self-contained: controllers, models, screens, services, widgets stay inside its folder
- ✅ Shared logic only goes in `core/`
- ✅ `booking.status` only accepts: `"pending"`, `"done"`, `"Cancelled"`
- ✅ `booking.date` must always be a future Timestamp — enforce both client-side and in Security Rules
- ✅ `addOns.priceType` only accepts: `"per_booking"`, `"per_person"`
- ✅ Every screen must have a `_test.dart` counterpart
- ✅ Run `flutter pub run build_runner build --delete-conflicting-outputs` after every freezed or Riverpod file change

| File | Agent | Role |
|---|---|---|
| `architect.md` | Architect | Schema design, folder structure, ADRs — no implementation code |

## CI/CD Pipeline

File: `.github/workflows/ci.yml`

Steps (run on every PR to `main`):
1. `flutter pub get`
2. `dart format --set-exit-if-changed .`
3. `flutter analyze`
4. `flutter test --coverage`
5. Coverage check: domain layer must exceed 80%
